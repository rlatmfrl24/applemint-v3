# 북마크 정기 분할 재분류 설계

2026-11-19 KST · 승인된 설계

## 목적

소유자가 기존 북마크를 정해진 수량씩 분류하고, 현재 소속과 제안 소속을 비교해 직접 승인할 수 있게 한다. 설정에서 시작한 작업은 브라우저를 닫아도 계속 진행된다. 이전 전체 분류는 처음에 33,508건을 등록하고 청구가 불확실해진 뒤 60건에서 중지됐다. 이번에는 필요한 회차만 등록하고 같은 문제가 생기면 그 회차에서 멈춘다.

사용자가 **매일 소량 작업 등록**과 **소유자 확인을 거친 회차 종료**를 선택했다. 수량, 시간, 처리 순서, 재개 동작은 아래 기준을 적용한다.

## 접근 방식

| 방식 | 운영상 차이 |
| --- | --- |
| 매일 소량 작업 등록 | 기존 분 단위 스케줄러가 하루에 한 번 설정 수량까지 등록한다. 작업 기록에서 날짜별 진행과 실패를 알 수 있고, 이전 회차에 처리가 남아 있으면 다음 등록을 보류한다. **선택한 방식이다.** |
| 단일 전체 작업에 일일 한도 적용 | 전체 진행을 한 작업에서 볼 수 있다. 초기 등록량은 전체 북마크 수에 비례하고, 같은 작업이 여러 달 동안 재개와 취소를 관리해야 한다. |

## 사용자 흐름

1. Settings의 북마크 설정에서 **정기 재분류**를 켠다. 기본값은 꺼짐이고 기본 수량은 **회차당 100건**이다. 수량은 1–500건 사이에서 설정한다. 실행 기준은 매일 **09:00 KST 이후**다.
2. 첫 활성화 시각까지 보관함에 저장된 북마크를 이번 회차들의 대상으로 삼는다. 과거에 저장된 것부터 순서대로 분류한다. 설정에서 다음 실행 가능 시각과 최근 회차 상태를 보고, 기존 작업 기록에서 처리 건수와 대기·실패 사유를 확인한다.
3. 기존 검토 화면의 **컬렉션 제안**에서 현재 소속, 제안 소속, 분류 이유를 비교한다. 소유자가 제안을 승인하면 이동하고, 제외하면 제안 기록을 정리한다. 자동 재분류가 이미 완료한 북마크는 같은 실행 범위에서 다시 등록하지 않는다.
4. 기능을 끄면 다음 등록과 새 비용 예약이 중단된다. 이미 비용 예약이 승인된 모델 요청은 기존 절차로 결과 검증과 정산을 마친다. 남은 항목과 기준 시각은 유지하며, 다시 켜면 일시 정지했던 회차부터 이어간다. 오류로 중단된 회차의 재개는 작업 기록에서 별도로 선택한다.

한 차례 대상을 모두 확인하면 상태를 **대상 확인 완료**로 표시한다. 활성화 뒤 새로 저장된 북마크는 기존 저장 추천 흐름을 이용한다. 같은 라이브러리 전체를 다시 순환하는 기능은 별도 요구로 다룬다. 하루 수량은 새로 등록하는 북마크의 상한이다. 이전 회차의 남은 항목은 그 회차 수량에 속한다.

## 분류와 제안 계약

저장 추천과 수동 분류가 사용하는 현행 정책을 공유한다.

| 조건 | 선택 |
| --- | --- |
| 기존 주제 컬렉션이 맞는다 | 해당 주제 컬렉션 |
| 주제가 없고 등록 커뮤니티 호스트에 맞는 활성 출처 폴더가 최상위 `Community` 바로 아래 하나 있다 | 그 출처 폴더 |
| 주제와 유일한 출처 폴더가 없는 커뮤니티 글이다 | 활성 `Community / etc`가 유일할 때 해당 폴더 |
| 맞는 주제가 없는 일반 링크다 | 활성 최상위 `etc`가 유일할 때 해당 폴더 |

사용자는 현재 소속과 다른 활성 컬렉션을 선택한 결과만 이동 제안으로 받는다. 같은 소속이면 제안 없이 완료한다. 자동 목적지를 결정할 수 없는 경우에도 제안 없이 분류 사유를 남긴다. 이미 검토 중인 유효한 수동 제안은 자동 분류보다 우선한다. 기존 저장·수동 분류·휴지통·승인 작업의 진입점과 권한을 유지한다. 승인 시 북마크 버전과 목적지의 활성 상태를 다시 확인한다. 목적지 이름이나 상위 경로가 바뀌었다면 검토 화면의 현재 경로를 기준으로 소유자가 승인 여부를 결정한다.

## 대상과 스케줄

- 기존 `applemint-bookmark-worker` cron과 `dispatch_bookmark_worker()`를 재사용한다. 자동 링크 점검의 설정과 출처 구분은 그대로 사용한다. 정기 분류는 `kind='classify'`, `scope='selected'`, `origin='scheduled-classify'`로 기존 작업 테이블에 등록한다.
- 설정의 활성 여부, 최초 활성화 시각, 수량, 마지막으로 대상으로 조회한 KST 날짜를 영속화한다. 설정 변경과 큐 등록을 직렬화한다. 대상 조회와 작업·항목 등록은 한 트랜잭션에서 수행하고 예약 작업의 KST 날짜에 고유 제약을 둔다.
- 09:00 이후의 첫 유효 실행에서 상태가 `library`이고 최초 활성화 시각까지 생성된 북마크 중, 정기 분류 작업에 등록한 이력이 없는 항목을 고른다. `saved_at, id` 오름차순으로 설정 수량까지 선택한다. 승인 대기 중인 현재 버전의 분류 제안과 다른 활성 분류 작업에 속한 항목은 후보에서 잠시 뺀다. 새 작업 수는 최대 하루 한 건이다.
- 처리 중, 재시도 중, 중단 중이거나 미처리·실패 항목이 남아 재개할 수 있는 기존 **정기 분류 회차**는 한 건만 유지한다. 과거 전체 분류와 수동 작업의 중지 이력은 새 정기 실행의 차단 조건에서 빠진다. 다만 같은 항목에 유효한 진행 중 작업이 있으면 해당 항목을 제외한다. 소유자가 종료한 정기 회차도 차단 조건에서 빠진다.
- 09:00 이후 준비된 후보를 한 번 조회하고 후보가 없으면 빈 작업을 만들지 않는다. 유효한 검토 대기나 수동 작업 때문에 건너뛴 후보는 남은 대상으로 계산한다. 처리 대상이 전부 소진된 경우에만 대상 확인 완료를 표시한다.
- 한 회차가 정기 큐에 등록한 ID는 성공·제안 제외·실패 여부에 관계없이 새 정기 작업으로 자동 등록하지 않는다. 실패는 같은 작업의 재개로 처리하고, 소유자가 종료한 회차의 미완료 ID는 수동 분류로 다시 선택할 수 있다. 목록 전체에 작업 행을 미리 만들 필요가 없다.

## 실행, 장애, 정산

- 자동 작업은 저장 추천과 기존 수동 작업이 우선 처리된 뒤 실행한다. 모델 요청당 기존 최대 20건과 입력 한도를 사용한다. 대상 URL, 버전 또는 소속이 중간에 바뀌거나 항목이 휴지통으로 이동하면 오래된 제안을 게시하지 않는다. 작업에 남은 사유를 통해 소유자가 재개할 수 있다.
- 기존 달력 월 **$1 공유 AI 예산**을 KST 기준으로 사용한다. 기존 예약이 성공한 뒤에만 OpenRouter에 요청하고, 알려진 금액과 불확실 예약은 기존 장부에 남긴다. 예약과 설정 변경을 직렬화해 끈 뒤 신규 예약을 막는다. 비용 예약 성공 시점을 이미 시작된 요청의 기준으로 삼는다.
- 예산 부족, AI 응답 유실, 청구 불명확, 공급자 설정 오류는 처리한 결과를 보존하고 해당 회차를 중단한다. 다음 날짜가 돼도 같은 실패 요청을 자동으로 호출하거나 다음 정기 회차를 만들지 않는다. 예산이 새로 확보되거나 오류를 확인한 소유자가 작업 기록에서 같은 회차를 직접 재개한다. 청구를 확인하지 못한 작업은 재개 전 예약 유지와 재호출 가능성을 표시한다.
- 복구할 수 없는 정기 회차는 소유자가 작업 기록에서 **회차 종료**를 선택할 수 있다. 종료는 활성 워커가 없는 중단·실패·일부 완료 회차에만 허용한다. 완료 결과, 제안, 정산 장부는 보존하고 남은 항목은 소유자 종료 사유와 함께 기록한다. 종료된 회차의 재개는 막고, 다음 KST 날짜의 정기 실행부터 다른 후보를 처리한다. 이 동작은 확인을 거쳐 실행한다.
- 게시하기 전 기존 컬렉션 경로 검증과 북마크 버전 검사를 실행한다. 같은 항목에 다른 작업이 유효한 제안을 먼저 게시하면 정기 결과는 중복 제안 없이 기록한다. 분류 중에는 `bookmark_jobs`, `bookmark_job_items`, AI 예약과 제안만 기록한다. 소속 및 이동 이력 변경은 기존 소유자 승인 경로만 담당한다.

## 검증 기준

- 스케줄러가 꺼져 있거나 09:00 이전이면 등록 0건. 동일 KST 날짜의 동시 실행은 작업 하나와 설정 수량 이하의 항목을 만든다. 기존 대량 작업의 재개가 없어도 새로운 첫 회차가 시작된다.
- 수동 분류 진행, 유효한 제안, 회차 완료, 불확실 요청, 명시적 제외 상태를 구분한다. 후보 0건에서 빈 작업이 없고, 처리한 ID가 다음 회차에서 다시 선택되지 않는다. 다음 달로 넘어가도 청구 불명확 요청의 자동 재호출은 0회다.
- 다음 회차를 시작하기 전에 설정 수량이 지켜지고, 예산 부족으로 중단한 뒤 결과와 예약이 보존되는지 DB에서 확인한다. 비활성화 뒤 이미 예약한 묶음은 정산되고 신규 예약은 멈춘다. 소유자가 회차를 종료하면 미확인 비용 기록을 유지하며 다음 날 새 후보만 등록한다.
- 격리 환경에서 소유자가 설정을 활성화하면 기존 스케줄러를 거쳐 실제 모델 분류가 실행된다. 주제, 등록 출처, 커뮤니티 기타, 일반 기타 및 동일 소속 사례를 확인한다. 승인 전 소속은 그대로이며 승인한 항목만 새 소속을 갖는지 화면과 DB에서 대조한다. 한 제안을 제외하고 다음 회차에도 다시 생기지 않는지 확인한다.
- 소유자 권한, 가져온 북마크의 날짜, 기존 수동 흐름, 설정 껐다 켜기, 승인 전 URL·컬렉션 변경을 회귀 검증한다. 운영 활성화와 이전 전체 작업 처리는 별도 운영 결정이다.
