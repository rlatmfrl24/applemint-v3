# 북마크 주제 우선 분류 설계

커뮤니티에 올라온 글도 사용자가 다시 찾을 주제의 컬렉션에 둔다. 아카라이브의 ‘블아 총력전 공략’은 `블루 아카이브`로, 같은 사이트에서 맞는 주제 컬렉션이 없는 일반 유머 글은 `etc`로 추천한다.

## 접근 방식

1. **모델이 최종 대상을 선택.** 저장 추천과 관리자 분류에 같은 지침과 예시를 준다. 변경량은 작고 `etc`의 적용 기준이 두 모델의 해석에 달려 있다.
2. **모델이 주제를 판단하고 서버가 `etc`를 결정.** 모델은 기존 주제에 맞는지 답한다. 서버는 응답을 검증한 뒤 커뮤니티 글의 `etc` 배치 여부를 같은 코드로 결정한다. 사용자와 합의한 방식이다.

## 분류 기준

| 검증된 입력과 판단 | 저장 팝업 | 관리자의 AI 컬렉션 분류 |
| --- | --- | --- |
| 글의 주제에 맞는 기존 컬렉션이 있다 | 해당 컬렉션을 추천한다 | 해당 컬렉션으로 이동을 제안한다 |
| 주제에 맞는 기존 컬렉션이 없는 커뮤니티 글이고 활성 `etc`가 하나다 | `etc`를 추천한다 | `etc`로 이동을 제안한다 |
| 주제에 맞는 기존 컬렉션이 없는 커뮤니티 글이고 활성 `etc`가 없거나 여러 개다 | 미분류 상태에서 직접 선택할 수 있다 | 사유를 작업 항목에 기록한다. 승인할 이동안은 발행하지 않는다 |
| 일반 링크이거나 커뮤니티 출처를 판단할 수 없고 기존 주제에 맞지 않는다 | 미분류를 제안한다 | 현재처럼 의미 있는 새 주제 컬렉션 또는 미분류를 제안할 수 있다 |
| 공급자 오류, 예산 부족, 무효한 응답 또는 추천 대상 변경 | 기존 오류·수동 저장 흐름을 사용한다 | 기존 작업 실패·중단·재개 흐름을 사용한다 |

- 제목, 설명, 태그, 주제를 나타내는 URL 경로 중 각 경로가 이미 가진 근거를 쓴다. ‘블아’는 `블루 아카이브`를 가리킬 수 있고, 관련 공략·캐릭터·이벤트 문맥이나 전용 게시판 경로도 근거가 된다. 주제 일치를 판단할 때는 글의 핵심 내용을 드러내는 단서가 필요하다. 관심 주제는 콘텐츠 근거를 보완한다.
- 서버는 HTTP(S) 원본 URL과 기존 커뮤니티 사이트 목록으로 등록 출처를 확정한다. 등록되지 않은 호스트도 주제 분류에 참여한다. 모델이 포럼 글 등 커뮤니티 게시물임을 뒷받침하는 단서를 식별한 경우 서버가 같은 `etc` 정책을 적용한다. 수집기 태그나 유사 도메인만으로 커뮤니티 출처를 확정하지 않는다.
- `etc`, `Community`·`커뮤니티`, 등록 커뮤니티 이름·호스트에 해당하는 출처 폴더 자체는 주제 후보에서 제외한다. `Community / 블루 아카이브`처럼 하위 이름이 주제를 나타내면 후보에 포함하고 전체 경로로 구분한다. 미등록 커뮤니티는 모델에 URL 호스트와 일치하는 이름만을 근거로 선택하지 않도록 지시한다.
- `etc`는 활성 컬렉션 이름을 앞뒤 공백과 대소문자를 무시해 비교하고, 정확히 하나일 때 기존 ID를 사용한다. DB가 모델 응답을 게시하기 전에 컬렉션 변경과 같은 잠금 안에서 같은 대상이 여전히 유일한지 확인한다. 관리자에서 이미 그 `etc`에 속한 글은 현재 소속을 유지한다.

## 적용 경로

- **Main·Quick의 북마크 저장.** 공통 팝업이 기존 서버 추천 작업을 시작한다. 사이트 이름만으로 팝업에서 먼저 목적지를 확정하던 분기를 제거한다. Jev는 선택 가능한 주제 컬렉션과 ‘기존 주제 없음’에서 고르고, 서버가 `etc` 규칙을 적용한 뒤 결과 ID와 컬렉션 버전을 게시한다. 사용자는 트리에서 확인·변경하고 명시적으로 저장한다.
- **북마크 관리자의 AI 컬렉션 분류.** 사용자가 고른 작업 범위에서 GPT가 각 북마크의 주제와 기존 대상 또는 새 주제 후보를 반환한다. 서버가 대상 자격과 커뮤니티 규칙을 검증해 제안을 게시한다. 사용자가 승인하면 DB에 실제 이동이 반영된다. `etc` 이동 제안에는 서버가 적용한 이유를 표시한다.
- 두 경로는 기존 소유자 인증, 원본과 컬렉션 검증, 요청 중복 방지, 작업·청구 처리, KST 월 $1 한도를 사용한다. 저장 팝업은 추천 대상 버전을 확인하고, 관리자는 북마크 버전과 대상 컬렉션의 활성 상태를 확인한다. 저장 팝업에서 사이트 이름만으로 무료 선택하던 링크도 추천을 요청하므로 해당 링크의 추천 대기와 AI 사용량이 늘 수 있다. 수동 저장은 기존 방식으로 가능하다.
- 범위는 새 추천과 사용자가 시작한 관리자 분류에 한정한다. 기존 결과는 작업 이력에 남고, 기존 북마크는 사용자 승인으로 이동한다. 기존 DB 스키마와 두 공급자 연결을 사용한다. 본문 수집, 전체 라이브러리 재분류, 새 설정 UI는 범위 밖이다.

## 완료 기준

- 사용 가능한 실제 컬렉션에서 평가 대상과 기대 ID를 호출 전에 기록한다. 블아를 줄임말로 쓴 글, 같은 커뮤니티의 일반 글, 다른 주제 컬렉션에 들어갈 커뮤니티 글, 일반 링크 대조군을 포함한다. 앱에 출처명 폴더가 있는 커뮤니티 글을 포함한다.
- Main에서 추천 확인 후 저장하고, Quick에서도 같은 진입을 확인한다. 관리자에서는 실제 모델로 분류해 제안 대상과 사유를 확인하고 승인한다. 사전에 정한 기대 ID를 기준으로 두 경로 각각을 판정한다.
- 새로고침 후 소유자 DB의 컬렉션 ID, 관리자 제안의 승인 기록과 추천 비용 영수증을 대조한다. 실패 응답과 `etc` 없음·중복, 수동 선택에 늦은 응답이 섞이는 경우는 별도 회귀로 검증한다. 모의 응답은 모델 정확도를 판정하는 데 사용하지 않는다.
