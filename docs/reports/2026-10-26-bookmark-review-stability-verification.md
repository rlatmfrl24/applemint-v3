# 북마크 화면 정리·검토 목록 안정화 검증

기준 `0cb24f9ce577c6b212f73bc5846af9cec51c3733` 이후 `codex/bookmark-review-stability`에서 승인된 주석 8개와 구현 계획을 적용했다. 현재 결과는 로컬 구현·검증 완료이며 push, PR 생성, 병합, 운영 마이그레이션·배포는 수행하지 않았다.

## 사용자에게 보이는 변경

- 북마크/검토 탭을 제목 옆으로 옮기고 우측 부가 문구·작업 기록 링크를 제거했다. 작업 기록은 설정의 기존 링크로 접근한다.
- 사이드바 컬렉션 검색과 검토 검색을 제거했다. 일반 목록·휴지통 및 저장/이동 대화상자의 검색은 유지한다. 검토의 옛 search URL 조건도 제거한다.
- 기본 범위는 구체적인 실패 근거가 재확인된 문제 링크다. 확인 필요·보관 정리·컬렉션 제안을 분리하며 저장 기간을 미사용으로 단정하지 않는다.
- 근거 전용 버튼을 제거했다. 제목에서 검사 근거를 열고 분류 제안 행은 변경안 버튼으로 승인할 수 있다.
- 검사 결과 게시가 목록을 다시 읽지 않는다. 현재 목록·선택·스크롤을 유지하고 새 결과 보기를 누르면 첫 100개만 조회한다. 성공 시 교체하고 실패 시 기존 화면을 보존한다.
- URL 열기는 열람 필드만 캐시에 병합한다. 늦은 응답이 최신 열람 횟수·시각·검토 revision 또는 제목을 되돌리지 않는다.
- 유지·삭제·복원·승인 후 정합성 조회, optimistic rollback, 삭제 실행 취소, evidence revision 충돌 검증은 유지한다. 자동 삭제·영구 삭제·추가 유료 AI 실행은 없다.

## 서버와 호환성

owner tRPC → service/repository → Supabase RPC 경계를 유지한다. 선택적 reviewGroup(problems/attention/organize/classify)을 추가하고 생략한 API 호출에는 기존 reviewType 의미를 유지한다. 최신 검사 계산을 관측당 수행하는 기존 집합 기반 조회와 필터·건수·페이지 일치를 보존한다.

신규 `20261026010000_bookmark_review_groups.sql` 한 개는 검토 조회와 비공개 판별 함수만 변경한다. 북마크·검사 원본·판정기·예산·자동 검사 설정을 변경하지 않는다. 문제 조건은 현재 버전/URL의 미검토 검사, confirmation=repeated, HTTP 404/410·NXDOMAIN, complete 본문 삭제/변경 의심 또는 실제 missing>0 미디어 누락이다. 구형·접근 제한·미확정 결과는 확인 필요로 보낸다.

KST 월 상한 **1,000,000,000 nano-dollar($1)**와 기존 자동 검사 일정·검사량을 유지한다. jobs 폴링은 작업 기록 5초, 기타 진행 작업 존재 시 15초/없을 때 60초이며 background 폴링은 하지 않는다.

## 독립 검토와 수정

독립 검토는 Critical 없음, Important 1건이었다. TanStack Query가 observer 이탈로 취소한 조회를 과거 캐시로 resolve할 수 있어, 취소된 조회를 성공으로 오인하고 유지/삭제 보호 상태를 해제하는 경계였다. observer 전환/화면 이탈의 실패 회귀 2개와 다른 활성 목록 회귀를 RED→GREEN으로 확인했다. 실제 read 완료·signal 미취소를 확인하고 다른 활성 목록이 남으면 보호 상태를 유지한다. 최종 전체 검사를 다시 통과했다.

기존 정적 E2E 경계 검사의 `.from(` 문자열 검출은 표준 `Array.from()`까지 차단했다. 실제 Data API 접근 금지와 Supabase import/secret 금지·검증된 로컬 docker/psql 경계는 유지하면서 표준 함수 오탐만 수정했다. 제품 코드를 검사에 맞춰 우회하지 않았다.

## 로컬 적용과 운영 반영 조건

기존 로컬 DB schema를 ignored reports에 백업한 뒤 새 마이그레이션을 적용했다. DB reset·기존 로그인 계정 변경은 하지 않았다. CLI의 로컬 연결 오류 후, 저장된 두 함수 본문과 migration이 CRLF 정규화 외에 일치함을 확인하고 로컬 migration history에 해당 버전 하나를 기록했다. readback으로 확인했다.

운영 반영 시 **마이그레이션 → 새 UI 배포** 순서를 지킨다. 이번 작업에서는 운영 DB·배포·설정에 쓰지 않았으며 운영 로그인 후 화면과 운영 부하에서의 체감은 검증하지 않았다. 로그·화면·schema 백업·실행 ledger는 ignored `reports/bookmark-review-stability/`에 보존한다. 브랜치와 managed worktree를 유지한다.
