# 북마크 검토 목록 정리 흐름 개선

기존 성능 개선 커밋 `356edc7` 다음 변경이며, `codex/bookmark-review-performance` 브랜치에 유지한다. 운영 배포와 원격 push는 수행하지 않았다.

## 사용자에게 보이는 동작

- 검토 행에 **삭제** 버튼을 직접 표시한다. 누르면 즉시 목록에서 빠지고 휴지통으로 이동한다. 기존 **실행 취소**로 복원할 수 있다.
- **유지**는 북마크의 내용·소속을 그대로 보존하고 검토 목록에서 즉시 제외한다. 기존 대기 제안도 적용 없이 제외하여 새로고침 후 다시 나타나지 않게 한다.
- 이후 새 검사나 새 제안에서 검토 사유가 생기면 다시 검토할 수 있다. 영구적인 검사 제외가 아니다.
- 행·일괄 처리·상세 화면이 같은 변경 경로를 사용한다. 저장 실패 시 해당 항목의 임시 제외를 취소하고 최신 근거를 다시 읽는다.
- 자동 삭제, 영구 삭제, 추가 AI 호출을 도입하지 않았다. 기존 월 $1 공유 예산과 소유자·북마크 버전·검사 근거 버전 검증을 유지한다.

## 원인과 수정

기존 keep 명령은 미사용 제안만 제외하고 분류 제안은 pending 상태로 남겼다. 검토 목록의 분류 조건이 계속 참이어서 유지 직후 재조회하면 다시 나타났다. 추가 마이그레이션 `20261025230514_bookmark_review_quick_cleanup.sql`은 기존 명령의 keep 분기에서 대기 제안을 모두 제외한다. 변경안 승인·북마크 본문 수정은 수행하지 않는다.

화면은 기존 낙관적 변경 저장소에 keep 동작을 추가했다. 독립 리뷰에서 목록 재조회가 한 번 실패하면 유지의 임시 화면 상태가 남아 이후 검사 결과를 가릴 수 있는 경로를 재현했다. 작업 결과 자동 갱신에서도 기존 `refreshBookmarkChanges`를 호출하여 성공적인 재조회 후 임시 상태를 해제한다. 진행 중인 변경이나 계속 실패하는 재조회는 잘못 성공 처리하지 않는다.

## 검증 결과

- TDD: 직접 삭제 버튼 누락, 유지 후 목록 잔류, 검사 근거 전달 누락, 실패한 조회 후 임시 제외 잔류를 실패하는 테스트로 확인한 뒤 수정했다.
- 최종 `pnpm check`: PASS. Biome·미사용 코드·타입 검사 통과.
- 최종 `pnpm verify`: PASS. Vitest 1,032개 통과·기존 3개 건너뜀, pgTAP 917개/42파일 통과, 생성 타입 확인·프로덕션 빌드·tRPC 경계·번들 제한 통과.
- 독립 코드 리뷰: PASS. 발견한 임시 상태 잔류 문제 수정 후 관련 테스트 26개도 별도로 통과했다.
- 운영과 분리된 기존 로컬 Supabase에 새 마이그레이션을 적용하고 실제 소유자 로그인 화면 `http://localhost:3001/main/bookmarks/review`에서 검증했다.
- 실제 화면: `격리 라이브러리 320`의 유지 버튼 → 즉시 0개 → 브라우저 새로고침 후에도 0개. DB에서 해당 북마크는 library·version 1, review_revision 1, keep 이벤트 1개로 확인했다.
- 실제 화면: `격리 라이브러리 319`의 직접 삭제 → 목록에서 제거 및 휴지통 이동 안내 → 실행 취소 → 같은 항목 복원. DB에서 library·version 3으로 확인했다.
- 검증 전후 북마크 수 404개 동일. `id/url/title/state/saved_at` 정렬 집계의 MD5도 `8965d6c6587f830085eef056ba071d0e`로 동일하여 원본 내용과 최종 보관 상태 보존을 확인했다. 변경·복원 이력과 버전 증가는 정상적으로 남는다.

## 근거와 남은 범위

로컬 실행 로그 및 화면은 ignored 경로 `reports/bookmark-review-performance/`에 보관했다. 대표 화면은 `cleanup-delete-undo.jpg`, `cleanup-keep-reload.jpg`이다. 검증에 사용한 브라우저 탭과 직접 시작한 미리보기 프로세스는 종료했다.

운영 DB 마이그레이션·배포는 수행하지 않았다. 모바일 실기기 레이아웃과 키보드 연속 정리의 사용성은 별도로 검증하지 않았다. 테스트나 mock이 실제 운영 배포의 증거를 대신하지 않는다. 사용자 요구와 다른 삭제·승인 흐름으로의 변경은 없다.
