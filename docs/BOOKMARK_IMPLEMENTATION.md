# Applemint 북마크 구현·운영 기록

Applemint DB를 북마크 원본으로 사용한다. Raindrop은 최초 한 번 읽으며 후속 동기화와 되쓰기는 없다. 기존 Quick Save는 수집 글 상태 이동 기능으로 유지한다.

현재 AI 공급자는 **OpenRouter**다. 저장 추천·관심 주제·컬렉션 분류·미사용 검토가 서버의 `OPENROUTER_API_KEY` 하나를 사용한다. 아래 실제 OpenAI 검증 기록은 공급자 전환 전 기록이며 OpenRouter 호출 증거가 아니다.

## 2026-10-15 현재 UI 계약

[재설계 계획](superpowers/plans/2026-10-15-bookmark-ux-redesign.md)과 [디자인 QA](../design-qa.md)를 기준으로 한다. 아래 날짜별 내용은 이전 구현 기록이다.

- 데스크톱 컬렉션 240px·목록·선택 상세 360px, 태블릿/모바일 Drawer. 제목과 행 클릭으로 상세를 열고, 주소 링크는 새 탭에서 원문을 연다. 현재 컬렉션은 별도 배지, 이동·삭제 전 경로는 상세의 ‘이전 컬렉션’으로 구분한다. 상세에서 전체 주소·경로를 확인하고 복사하며 모바일은 명시적 이동 버튼을 사용한다.
- 컬렉션 검색·전체 경로·경로 탐색, 250ms 한글 조합 검색, 초기/갱신/추가 로딩과 빈 상태를 구분한다. 기존 100개 추가 로딩·2,000개 선택을 유지한다.
- Main/Quick 저장 창은 유일한 사이트 일치를 무료 선택하고, 그 외 자동 AI 추천한다. 결과 적용까지 컬렉션·저장만 잠그고 같은 탭의 원본·제목별 requestId와 작업을 재사용한다. 30초 뒤 명시적 수동 전환은 서버 취소가 아니다. 최초 코드 로딩에도 취소 가능한 모달을 표시하며 폼 전체는 클라이언트에서 지연 로딩한다.
- 이동·휴지통·복원은 원본 페이지/offset을 변경하지 않는 작업별 표시 계층을 사용한다. 성공 뒤 조회 실패는 저장 실패로 되돌리지 않는다. 단건 휴지통 취소에는 서버 응답 버전을 사용한다.
- 설정의 관심 주제는 버전 단위로 변경하며 실패 시 입력을 보존한다. 이미 등록한 추천은 제외하고, AI 설정 여부와 실제 월 예산/정산/예약/요청 요약을 먼저 보여준다. 상세 모델 통계는 펼칠 때만 불러온다.
- 소유자 검증, 원본 URL·수집 글 보존, 제안 승인·유지 구분, 서버 버전 검사와 월 $1 예산·불명확 예약액은 변경하지 않았다. DB 마이그레이션과 새 의존성은 없다.
- 실자료 DB를 초기화하지 않는다. 검증은 실행 중인 로컬 서버에서 `pnpm exec playwright test --config playwright.bookmarks.config.ts`를 사용한다. 일반 `pnpm test:e2e`는 이 검증에 사용하지 않는다.

## 사용 흐름

| 진입점 | 사용자 동작과 저장 결과 |
|---|---|
| `/main/bookmarks` | 컬렉션 아코디언 탐색, 팝업 생성·이름 수정·삭제, 촘촘한 목록·검색·100개 단위 페이지·개별 수정·일괄 휴지통 이동 |
| 수집 글의 북마크 저장 | 같은 저장 창을 사용한다. 서버가 수집 글 URL을 재확인하며 원래 글의 상태는 유지한다. |
| 북마크의 링크 검사 | 기본 범위는 선택 항목이며 미선택 시 실행할 수 없다. 전체·현재 컬렉션 범위도 지정할 수 있다. AI 작업은 보조 메뉴에 있다. |
| `/main/bookmarks/review` | 유형별 필터, 근거·소속 경로, 유지·휴지통·제안 승인/제외. 상세 근거와 AI 대상 수정은 팝업에서 처리한다. |
| `/main/bookmarks/trash` | 소속과 삭제 전 소속을 확인하고 개별·일괄 복원한다. 컬렉션 트리·관리 메뉴는 없다. |
| `/main/bookmarks/activity` | 보조 작업 기록 화면에서 진행·실패 항목·재개를 확인한다. 북마크·검토 목록에는 작업 로그를 펼치지 않는다. |
| 유지·휴지통·복원 | 사용자 선택만 DB에 반영한다. 같은 검토의 유지 결과는 다시 미처리로 표시하지 않으며 복원 시 메모·태그·소속을 보존한다. 선택 항목 일괄 처리를 제공한다. |
| AI 컬렉션 분류 | 현재 소속 → 제안 소속과 이유를 확인한다. 이름·대상 수정 후 개별 승인, 선택한 북마크마다 최신 유효 원안 한 개의 일괄 승인·제외를 제공한다. |
| `/main/setting/bookmarks` | 최초 이관 진행·관심 주제 확정·AI 예산은 유지하고 일반 작업은 작업 기록으로 연결한다. 기존 Setting 메뉴로 접근한다. |

직접 저장은 같은 정규화 URL이 있으면 기존 항목을 안내한다. Raindrop의 서로 다른 원본 ID가 같은 URL을 가리키는 자료는 모두 보존한다. 제목·설명 수집은 DB 저장 뒤 별도 작업이며 실패해도 저장한 자료는 남는다. ‘열기’는 버튼 사용 기록이며 방문 완료·완독의 증거가 아니다.

Raindrop 미분류는 Applemint의 같은 미분류 보기로 합친다. 이관 원본의 미분류 ID·소속 기록은 별도로 남으며 화면과 AI에는 중복된 미분류 컬렉션을 만들지 않는다.

## 데이터와 권한

- `bookmarks`, `bookmark_collections`는 수집 글과 별도 원본이다. `original`과 `source_id`에 가져온 정보·원래 계층·소속을 남기고 현재 분류와 휴지통 상태는 별도로 관리한다.
- `bookmark_jobs`, `bookmark_job_items`가 작업·진행·재시도·실패 결과를 보존한다. YouTube queue를 재사용하지 않는다.
- `bookmark_checks`, `bookmark_proposals`, `bookmark_events`가 검사·제안·검토·열기 이력을 보존한다. `bookmark_import_verifications`는 이관 완료 전 원본 ID와 소속을 대조한다.
- 소유자 tRPC는 `bookmark`, `bookmarkCollection`, `bookmarkImport`, `bookmarkCheck`, `bookmarkAI`, `bookmarkProposal`로 나뉜다. 사용자 DB 세션에는 RLS와 소유자 판정을 적용하며 쓰기는 `bookmark_command` RPC만 수행한다.
- 일반 tRPC 의존성에는 service-role 클라이언트를 넣지 않는다. worker는 내부 인증 후 서버 권한으로 허용된 RPC만 호출하며 북마크 테이블 직접 권한을 갖지 않는다.

수정·휴지통·복원·분류 승인에는 북마크 버전을 확인한다. AI 검토는 열기·유지의 `review_revision`과 관심 주제 버전도 확인한다. worker와 승인 RPC는 같은 순서로 필요한 행을 잠그며 오래된 근거가 사용자 결정을 덮어쓰지 못한다. 일괄 변경은 모두 성공하거나 모두 롤백한다.

## 서버 설정과 작업 실행

`.env.example`을 기준으로 서버의 `RAINDROP_IMPORT_TOKEN`, `OPENROUTER_API_KEY`를 설정한다. `NEXT_PUBLIC_` 접두사를 사용하지 않는다. 설정 화면에는 존재 여부만 표시한다. 기존 `OPENAI_API_KEY`·`TYPESAFE_API_KEY`는 현재 Applemint AI에서 읽지 않는다.

worker는 `/api/bookmarks/worker`의 POST이며 `x-applemint-internal-secret`으로 32자 이상의 `CRAWL_INTERNAL_SECRET`을 검증한다. Supabase Cron은 1분마다 **이미 등록된 작업만** 진행한다. 예약 실행이 새 검사나 AI 작업을 만들지는 않는다.

Vault의 `bookmark_app_base_url`, `bookmark_internal_secret`을 서버 주소·내부 인증 값과 맞춘다. 없으면 기존 `crawl_app_base_url`, `crawl_internal_secret`을 사용한다. 로컬 Docker에서 호스트 서버에 연결할 때 주소는 `http://host.docker.internal:3000`이다. 비밀 값은 로그·문서·브라우저에 기록하지 않는다.

DB 변경은 다음 추가 migration에 있다. 로컬 DB에만 적용했으며 운영 적용과 배포는 수행하지 않았다.

1. `20261013015432_bookmark_library.sql`: 테이블·RLS·소유자 및 worker RPC·예산·Cron
2. `20261013020637_bookmark_worker_context.sql`: worker 전용 대조·태그 입력 조회
3. `20261013070000_bookmark_manager.sql`: 컬렉션 보관 삭제·이전 소속·수명주기 잠금·검토 유형별 조회
4. `20261013073000_bookmark_review_query.sql`: 전체 실자료의 검토 근거를 집합 단위로 집계하고 동일한 집계에서 수량·페이지를 반환

관리자에서는 URL 직접 입력·북마크 저장·설정 바로가기를 제공하지 않는다. 수집 글의 저장만 유지한다. 내부 상태 값 `library`와 소유자 RLS는 유지한다.

컬렉션 삭제는 소유자 원자적 RPC로 수행한다. 상태와 관계없이 직접 소속 북마크는 미분류로 옮기고 `previous_collection_path`에 삭제 전 경로를 보존한다. 직접 하위 컬렉션은 한 단계 위로 이동한다. 컬렉션은 `archived_at`으로 보관하고 원본 ID·이관 구조·승인 기록을 보존한다. 영향을 받은 버전은 증가시키며 미처리 제안은 제외한다. 삭제된 대상과 오래된 버전의 변경은 거부한다. 일반 명령·worker는 공유 수명주기 잠금을, 삭제는 배타 잠금을 행 잠금보다 먼저 얻고 외부 요청 중에는 잠금을 유지하지 않는다.

검토 조회는 죽은 링크 → 컬렉션 변경안 → 미사용 후보 순으로, 같은 유형에서는 저장 시점과 ID로 정렬한다. 유지 결과는 죽은 링크·미사용 근거를 처리하며 남은 컬렉션 변경안은 별도로 승인·제외한다. 선택은 현재 페이지에 한정하고 필터·페이지·화면 변경 시 초기화한다. 탭은 일반 브라우저 링크로 이동해 뒤로가기와 독립 URL을 유지한다. 세션 미들웨어는 Next.js 탐색 해시에 필요한 `next-url`을 보존하며 임의 권한 헤더는 전달하지 않는다.

북마크 전용 E2E는 `pnpm exec playwright test --config playwright.bookmarks.config.ts`로 실행한다. 기존 localhost:3000 서버·54321 로컬 API·소유자 로그인만 사용하고 DB 준비나 초기화는 실행하지 않는다. 실제 AI·외부 재검사·확인된 QA 정리는 각각 `BOOKMARK_LIVE_AI=1`, `BOOKMARK_LIVE_CHECK=1`, `BOOKMARK_CLEANUP=1`을 명시한 실행으로 제한한다. 일반 `test:e2e`는 초기화가 포함되므로 실자료가 있는 이 환경에서 실행하지 않는다.

2026-10-13 UI 개선 검증에서 컬렉션 생성·수정·삭제·자식 이동, 수집 글 상태·원본 보존, 열기·휴지통·복원, 검토 필터 수량·페이지·뒤로가기를 실제 화면과 소유자 DB 재조회로 확인했다. 실자료 검토 조회는 제한 시간 초과(약 8초)에서 173ms로 개선됐으며 전체 32,545건을 집계하고 100건을 반환했다. 1440×900에서는 완전히 보이는 북마크 9행을 확인했고, 375px의 네 화면에 가로 넘침이 없으며 팝업 키보드 초점이 돌아온다. 모바일 컬렉션 탐색은 접힌 상태로 시작한다.

실제 OpenAI 관심 주제 제안 10개와 수집 글 북마크 2건의 분류안을 검토 팝업에서 수정·승인했다. 원본·수집 글 ID·승인·컬렉션 반영을 DB에서 재조회했고 두 영수증은 정산됐으며 추가 비용은 895,225 nano-dollar($0.000895225)였다. 검증 후 기존 관심 주제는 복원했다. 지정한 `AI 검증 정리 1791868938290`, `AI 검증 정리 1791869523870`과 이번 임시 컬렉션을 삭제 팝업으로 정리했으며 북마크·태그·메모·원본·상태는 보존했다. Raindrop 원본 북마크 33,418건은 유지됐다. 실제 UI 스크린샷·백업·로그는 개인정보가 포함될 수 있어 ignored `reports/`에만 저장한다.

## UI 개선 최종 리뷰와 실행 판단

새 컨텍스트의 독립 리뷰는 컬렉션 수명주기·권한·정산에 추가 결함을 찾지 않았으며 화면 경계 세 건을 지적했다. 현재 페이지를 떠난 선택 항목의 실행 차단, 160자 컬렉션 이름의 모바일·삭제 팝업 넘침, 메뉴 Escape 초점 복귀를 실제 브라우저에서 실패로 재현한 뒤 수정했다. 회귀 검사 3건과 최종 전체 UI 검사 13건이 통과했다. 실제 AI·외부 링크 재검사·작업 재개는 앞선 별도 실행에서 확인했으며 마지막 일반 실행에서는 이를 반복 호출하지 않았다. 보류한 경미 결함은 없다.

실행 중 내린 판단은 다음과 같다.

- 실자료 전체 검토가 약 8초 뒤 실패하여 추가 migration으로 집합 집계를 도입했다. 필터·수량·페이지의 의미는 유지한다. 잘못될 경우 조회 회귀 위험이 있으므로 pgTAP과 실자료 UI를 대조했다.
- 세션 미들웨어에서 Next.js의 `next-url`을 보존했다. 잘못될 경우 탐색 회귀 위험이 있으므로 위조 권한 헤더 차단과 실제 탐색을 검증했다.
- 올바른 Flight 응답 이후에도 Next Link가 멈춰 기존 앱 메뉴와 같은 일반 링크를 북마크 탭의 기본 탐색으로 사용했다. 독립 URL·뒤로가기는 유지되며 페이지를 다시 불러오는 비용이 있다.
- 승인된 로컬 범위를 유지하여 운영 migration·배포는 수행하지 않았다. 운영에 적용할 때 해당 환경의 백업·적용·실제 경로 검증이 필요하다.
- 소량의 실제 AI 검증으로 범위를 유지했다. 전체 이관 자료의 분류 품질은 사용자 검토를 통해 추가로 확인해야 한다.
- 관련 없던 AGENTS·조사·질문지 파일과 원래 IssueLink 작업을 보존했다. 이번 검증 결과는 그 작업에 대한 판정이 아니다.

브라우저 테스트는 실제 사용자 조작·승인 후 소유자 DB로 재조회했으며 mock이 완료 증거를 대신하지 않았다. 전체 DB·인증·권한·예산 검사와 일반 tRPC의 서버 권한 격리를 유지한다. 공통 경로 표시에서 트리 전용 함수를 분리하고 수집 글 저장의 불필요한 분기를 제거해 기존 `/main` 용량 제한도 유지했다.

## 일회 이관과 재개

백업과 소량 조회 대조 후 설정 화면에서 시작한다. 최상위·하위·빈 컬렉션과 미분류를 포함하며 휴지통(-99)은 제외한다. 페이지는 50개씩 읽고 원본 ID로 중복 생성을 막는다. 중단된 작업의 재개는 최초 계정을 유지한 채 manifest와 첫 페이지부터 다시 읽는다. 이미 가져온 자료의 현재 분류·휴지통 상태·원본 기록은 덮어쓰지 않는다.

저장 이후 별도의 페이지 조회로 고유 원본 ID, 원래 소속, 수량과 컬렉션 ID·이름·부모 관계를 대조한다. 일치해야 `succeeded`이며 불일치는 `partial`이다. 완료 후 신규 이관을 거부하고 임시 토큰 제거를 안내한다.

Raindrop은 이 조회에 일관된 시점의 전체 snapshot을 제공하지 않는다. 이관·대조 중 원본을 수정하지 않는 것이 필요하다. 이미 가져온 원본을 삭제·이동했을 때 Applemint에서 자동 삭제하거나 원본 기록을 덮어써서 완료로 표시하지 않는다. 불일치는 확인 후 해결해야 한다.

## 링크 검사와 AI

HTTP·HTTPS만 요청하고 DNS 응답과 실제 연결 IP를 검증한다. 내부망·예약 주소와 위험한 리다이렉트를 차단한다. 전체 요청 제한은 10초, 리다이렉트는 최대 5회다. 404·410·확인된 NXDOMAIN은 1분 후 재검사해 후보로 표시한다. 로그인·봇 차단·시간 초과·5xx는 죽은 링크로 확정하지 않는다. HTTP 200은 응답 확인이며 내용 유효성의 증거가 아니다.

관심 주제·분류·검토는 OpenRouter `/api/v1/responses`의 `openai/gpt-6-luna`, `reasoning.effort=none`, 구조화 출력, `store=false`를 사용한다. 저장 추천은 같은 게이트웨이의 `/api/v1/systemone`·`typesafe/jev-1.13`을 사용한다. 제목·URL·태그·설명·컬렉션 구조·확정한 관심 주제만 분류 입력으로 사용한다. 관심 주제 제안에는 기존 태그 집계를 사용한다. 원문 전체 수집과 요약은 필수 조건이 아니다.

발송 전 입력의 UTF-8 바이트 수와 프로토콜 여유량으로 크기를 제한한다. OpenRouter에는 기존 토큰 계산 API가 없어 로컬 입력량 검사를 사용하며, GPT 호출은 최대 입력 128,000토큰과 최대 출력 8,192토큰 비용 **$0.020096**를 원자적으로 예약한다. 대상은 기본 20개씩 나누고 입력량이 크면 줄인다. KST 달력 월 $1을 정수 nano-dollar로 관리하고 OpenRouter가 보고한 `usage.cost`로 정산한다. 단가 상한을 요청에도 전달하며 더 비싼 경로로 전환하지 않는다. 청구가 불명확하면 예약액을 유지한다. 알려진 비용이 예약액을 초과하면 실제 금액을 보존하고 해당 월의 모든 신규 AI 예약을 차단해 공급자 비용 대조를 요구한다. 예산 부족이나 불명확한 요청은 직접 재개하며 완료된 제안은 남는다. 모델 오류를 규칙 분류의 성공으로 대체하지 않는다.

예산은 이 기능의 API 사용·예약에 대한 기준이다. 세금·환율·다른 앱 사용량을 포함하지 않는다. 전체 라이브러리를 한 달 안에 분류한다는 보장은 없다.

API 근거: [OpenRouter Responses](https://openrouter.ai/docs/api_reference/responses/overview), [구조화 출력](https://openrouter.ai/docs/guides/features/structured-outputs), [경로·가격 제한](https://openrouter.ai/docs/guides/routing/provider-selection), [사용량 정산](https://openrouter.ai/docs/cookbook/administration/usage-accounting), [Jev](https://openrouter.ai/docs/guides/community/jev).

## 2026-10-14 북마크 컬렉션 이동

오른쪽 북마크 행을 왼쪽 컬렉션 또는 미분류에 드래그하면 기존 소유자·버전 검사 RPC로 한 항목을 이동한다. 같은 소속에 놓으면 저장 요청과 버전 증가가 없다. 전체 북마크와 휴지통은 이동 대상이 아니다. 이동 성공·실패는 알림으로 표시하고 목록을 재조회한다. 이 최초 구현을 아래의 선택 묶음·컬렉션 계층 이동으로 확장했다.

항목 메뉴의 **컬렉션 이동**은 모바일·키보드용 동일 기능이다. **수정 → 컬렉션**에서도 부모·하위 컬렉션을 펼쳐 선택한다. 현재 소속의 조상은 처음부터 펼치며, 선택은 폼의 변경 저장 또는 이동을 눌러야 DB에 적용된다. 방향키·Home·End·Enter·Space를 지원하고 Escape는 선택 트리만 닫아 필드에 초점을 돌려준다.

실제 동시 수정 검증에서 기존 `40001` 충돌 응답이 PostgREST 14.17의 반복 재시도를 유발했다. 추가 migration `20261013230422_bookmark_conflict_http.sql`은 북마크 명령과 컬렉션 검증 함수의 업무 충돌만 `PT409`로 변경한다. 원자성·권한·잠금·버전 검사와 기존 함수 소유권·실행 권한은 유지한다. 원인과 응답 코드의 근거는 [Supabase 공식 안내](https://supabase.com/docs/guides/troubleshooting/high-cpu-and-infinite-transaction-retries-when-using-custom-error-codes-in-rpc-functions-77326b)이다. 적용 전 로컬 public·private 스키마와 데이터 백업을 reports에 저장했으며 실자료 DB는 초기화하지 않았다.

## 2026-10-22 북마크 본문·미디어 점검

기존 `링크 검사`에서 선택 항목·컬렉션·전체 범위를 검사한다. 접속, 본문, 미디어의 상태와 실제 관측 시각을 따로 저장하며 HTTP 200을 본문 정상으로 해석하지 않는다. 검토 화면의 본문 삭제·변경 의심, 미디어 소실·일부 실패, 접근 제한·판단 불가 필터에서 근거를 확인한 뒤 직접 유지·휴지통 이동·복원한다. 자동 삭제는 없다. 유지에는 본 검사 ID와 revision을 보내므로 화면을 연 뒤 바뀐 근거를 검토 완료로 숨기지 않는다.

북마크 설정에서 매일 자동 점검을 켠다. 최초 기본값은 꺼짐·500개/일, 허용 범위는 1–1,000개다. KST 09시 이후 기존 분 단위 cron이 한 번 등록하며 수동 검사와 진행 중 항목을 중복 등록하지 않는다. 기존 원문/미디어/재확인 대기를 먼저 처리하고, 다음 달 AI 예산 대기만 남은 작업은 새 원문 수집을 막지 않는다. 저장 추천과 사용자 작업이 자동 검사보다 우선한다. 설정을 꺼도 시작된 요청의 결과·비용 정산은 보존한다.

원문 512 KiB·미디어 응답 64 KiB, 항목당 미디어 최대 20개, 호스트별 한 요청·종료 후 2초 간격을 적용한다. 이동 응답도 SSRF/DNS/IP 검증과 호스트 제한을 따르며 대기 중 이동 지점을 checkpoint로 이어받는다. 일부 추출, JS 렌더링, 로그인·봇 차단, 지원하지 않는 embed는 판단 불가로 남긴다. 이미지 의미 및 영상 전체 재생은 확인하지 않는다. 직접 미디어 URL은 HTML 검사와 구분한다.

모호한 본문과 자동 정상 표본 최대 10건에 기존 Jev System One을 사용한다. 북마크 제목·본문 발췌·추출/미디어 지표만 보내고 메모·태그·URL query·쿠키는 보내지 않는다. 기존 KST 월 $1 공유 예산과 요청별 예약/실제 영수증 정산을 유지한다. 응답이 유실된 동일 근거는 자동 유료 재호출하지 않으며, 알려진 비용은 결과가 오래돼 적용할 수 없더라도 정산한다.
