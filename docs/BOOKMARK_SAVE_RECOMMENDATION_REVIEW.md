# Main·Quick 저장 시 Jev 컬렉션 추천

## 확정한 동작

Main·Quick의 공통 ‘북마크 저장’ 팝업에서 **‘추천받기’ → 컬렉션 자동 선택 → 트리에서 확인·수정 → 저장**을 수행한다. 하단 추천 상세와 별도 적용 버튼은 표시하지 않는다. 팝업을 열기만 해서는 AI를 호출하지 않는다. 호스트와 이름이 유일하게 일치하는 기존 컬렉션은 팝업의 기본 선택으로 반영한다. 새 컬렉션 생성과 전체 라이브러리 분류는 기존 관리자 흐름을 사용한다.

저장 추천 모델은 **Jev**이며 공급자는 모든 Applemint AI와 같은 **OpenRouter**다. 관심 주제·분류·검토는 같은 게이트웨이의 GPT-6 Luna를 사용하며 **KST 달력 월 $1 예산을 합산**한다. Jev 실패를 다른 모델이나 규칙 분류의 성공으로 대체하지 않는다.

일반 글의 제목 버튼과 URL은 모두 같은 `thread.url`을 연다. 별도의 ‘제목 링크 URL’ 필드는 없다. 추천 입력은 게시물 URL과 제목 텍스트이며, YouTube는 공식 메타데이터 제목을 별도로 포함한다.

## 사용자 흐름과 실패 처리

1. 저장 팝업은 컬렉션 트리를 제공한다. URL의 HTTP·HTTPS 호스트를 기존 사이트 목록으로 정규화하고 정확한 이름의 컬렉션이 하나일 때 기본 선택한다. `arca.live`는 `arcalive`, `v12.battlepage.com`은 `battlepage`로 찾는다. 일반 도메인의 전체 호스트 이름도 지원한다. 경로·쿼리의 단어, 유사 도메인과 중복 이름은 임의로 선택하지 않는다. 트리에서 직접 바꾸거나 미분류로 저장할 수 있다.
2. ‘추천받기’는 최신 컬렉션을 먼저 조회한다. 호스트가 일치하면 즉시 선택하며 AI 작업·예약·비용을 만들지 않는다. 조회 실패를 매칭 없음으로 해석해 유료 호출하지 않는다. 일치 대상이 없으면 소유자 API가 서버의 원본 URL·수집 제목·공식 제목과 사용자 수정 제목을 캡처하고 작업을 등록한다. 추천 작업은 북마크를 미리 생성하지 않는다.
3. Jev가 기존 컬렉션 또는 미분류를 제안하면 컬렉션 선택에 바로 반영한다. 경로는 트리 선택 버튼에서 확인하고, 근거·확신도 상세 패널은 표시하지 않는다. 모델 확신도는 DB 결과에 보존하며 정답률을 보장하지 않는다.
4. 추천 요청 뒤 입력을 바꾸지 않았을 때만 자동 반영한다. 늦은 응답은 후속 수동 선택·제목 변경을 덮어쓰지 않는다. 반영 직전 컬렉션을 재조회해 삭제·버전 변경을 거부한다. 반영 중에는 입력과 열린 트리를 잠그고 완료·실패 후 해제한다. 캐시된 완료 결과를 다시 열어도 잠금이 남지 않는다.
5. 트리 선택이나 제목 변경은 추천 확정 표식을 해제한다. 제목을 바꿔도 현재 보이는 컬렉션은 직접 확인해 저장할 수 있다. 추천과 저장은 제목 앞뒤 공백을 같은 방식으로 제거한다.
6. ‘저장’은 기존 소유자 tRPC와 원자적 RPC를 사용한다. 추천 ID·입력·대상 버전을 재검증하며 수집 글 상태는 바꾸지 않는다. 표시한 URL과 서버 원본 URL이 달라졌으면 저장을 거부해 다른 링크를 조용히 저장하지 않는다. 이미 저장한 URL은 기존 항목을 안내한다.
7. 팝업을 닫은 뒤에도 작업 기록의 ‘추천 확인·저장’에서 같은 추천을 다시 열 수 있다. 결과 조회·적용은 추가 AI 호출을 만들지 않는다. 실패 작업의 재개는 사용자가 요청한다.

키 미설정·예산 부족·추천 실패·결과 조회 실패에도 수동 저장은 가능하다. 결과 조회 실패는 ‘추천 결과 다시 확인’으로 읽기만 재시도한다. 청구가 불명확한 공급자 요청은 자동 재발송하지 않는다.
