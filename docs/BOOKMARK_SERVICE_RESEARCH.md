# Raindrop 유지와 Applemint 자체 북마크 서비스 비교

> 조사 기준: 2026-10-13, Asia/Seoul
> 범위: 공식 문서·공식 가격 조회와 Applemint 로컬 소스 분석. 기능 구현, 데이터 이전, 계정 변경, 결제는 수행하지 않음.
> 소스 기준: `03bb2dae9716d3b5fd3e34ed55f20166ba09ad75`. 서비스 설명은 확인된 사실, 개발 비용·우선순위·권고는 분석 판단으로 구분함.
> 사용자 조건 반영: 추가 구독 결제는 부담이며, 죽은 링크·미사용 링크 정리와 AI 컬렉션 생성·분류가 우선이다. 요약은 낮은 우선순위다.
> 확정 정책(2026-10-13): [설계 질문지](../to-questionnaire-bookmark-db-sync-cleanup.md)의 Q1~Q10 응답을 반영했다. Applemint DB가 최종 기준이며, Raindrop 휴지통을 제외한 자료를 최초 한 번 가져온 뒤 신규 저장·분류·정리는 Applemint에서 직접 수행한다. Raindrop 되쓰기와 후속 동기화는 운영하지 않는다.

## 확정한 방향

**Raindrop Free의 기존 자료를 Applemint DB로 일회 가져오고, 이후 신규 저장·죽은 링크 검사·미사용 후보 검토·AI 컬렉션 정리를 Applemint에서 수행하는 개인용 서비스로 결정했다.** Applemint DB가 분류·정리의 최종 기준이다. Raindrop 휴지통은 가져오지 않으며 외부 수정·이동·삭제나 이후 신규 항목을 동기화하지 않는다. 정리 결과도 Raindrop에 반영하지 않는다. 광범위한 기기별 클라이언트 재구축, Pro 구독, 전체 원문 아카이브와 요약은 현재 필수 범위로 삼지 않지만 Applemint의 실제 직접 저장 흐름은 반드시 완성해야 한다.

Pro 기능·가격과 아래 대안 A는 비교 이력으로 남겨 두며 채택한 구조의 필수 조건으로 삼지 않는다. Free 계정의 실제 API 접근과 이용 조건은 별도 확인이 필요하다. 접근에 문제가 생기면 최초 자료 이전 경로를 검토하되, Applemint의 신규 저장·분류·정리가 Raindrop을 거쳐야 작동하는 구조로 되돌리지 않는다. 분석 결과 파일만으로 실제 컬렉션 정리가 완료됐다고 보지 않는다.

## 1. 서로 다른 문제를 구분해야 한다

| 문제 | 판단에 필요한 근거 | 적절한 대응 |
| --- | --- | --- |
| 죽은 링크 | 반복 검사, 응답 상태, DNS, 실제 브라우저 접근 | 재검사 후 URL 수정·아카이브 확인·삭제 후보 표시 |
| 중복 북마크 | URL, 의미 있는 쿼리, 태그·메모 차이 | 대표 항목을 보존하고 부가 정보 확인 후 정리 |
| 오래된 북마크 | 저장 시점, 주제의 최신성 | 리뷰 후보로 올리기 |
| 사용하지 않는 북마크 | 관측된 열기 기록, 읽음 확인, 최근 리뷰 판단 | 유지·나중에·보관·삭제를 직접 선택 |
| 너무 많이 저장함 | 저장량과 실제 읽기·재사용의 차이 | 작은 리뷰 목록과 보관 기준 제공 |

**오래됨은 사용하지 않음의 증거가 아니다.** Raindrop의 문서화된 `lastUpdate`는 수정 시점이며 마지막 방문 시점이 아니다. 공개 필드만으로 과거의 읽기 이력을 복원할 수 있다고 볼 근거가 없다. Applemint도 현재 항목 계약과 링크 열기 흐름에서 방문·읽음·리뷰 이력을 확인하지 못했다. 따라서 기존 북마크의 과거 사용 상태는 우선 `알 수 없음`으로 취급해야 한다. [Raindrop 필드 계약](https://developer.raindrop.io/v1/raindrops), [Applemint 항목 계약](../contracts/thread.schema.ts), [링크 열기 UI](../app/main/thread-card.tsx)

열기 기록 역시 완독의 증거는 아니다. Applemint에서 열었는지와 사용자가 읽었다고 확인했는지를 구분해야 한다. 외부 브라우저에서 직접 방문한 기록은 별도 수집 경로가 없으면 관측할 수 없다. 이는 자체 개발에서도 남는 측정 한계다.

## 2. 현재 Raindrop의 기능과 비용

### 확인한 가격

| 요금제 | USD 기본 가격 | 비교 의미 |
| --- | --- | --- |
| Free | $0 | 저장·분류를 유지할 수 있지만 내장 정리·본문 검색·아카이브·Stella는 제공하지 않음 |
| Pro 월간 | $3/월 | 12개월 이용하면 기본 가격 합계 $36 |
| Pro 연간 | $28/년 | 월 환산 약 $2.33. 월간 12회 대비 $8 절감 |

가격은 공식 구매 페이지가 사용하는 Paddle의 **가격 미리보기**에서 확인했다. 두 상품의 `unit_price`는 각각 USD 300센트와 2,800센트, 과금 주기는 월 1회와 연 1회이며 세금 방식은 `external`이었다. 실제 결제는 지역 세금·통화·환율·구매 채널에 따라 달라질 수 있다. 한국 계정의 결제 화면 금액은 확인하지 않았다. [공식 가격 페이지](https://raindrop.io/pro/buy)

확인 경로: 공식 구매 페이지의 공개 스크립트가 `Paddle.PricePreview`에 사용하는 상품 ID `pri_01k8ws7yj8vjch6j8g10w86k5w`와 `pri_01k8ws8rjzraf6w3609avtfhb1`을 조회했다. 요청은 [Paddle 가격 미리보기 endpoint](https://api.paddle.com/pricing-preview)에 대한 읽기 목적의 POST이며 구매나 구독 생성은 하지 않았다. 이 상품 ID나 USD 금액은 이후 변경될 수 있다.

## 3. 주요 선택지 비교

아래의 난이도·운영 부담·권고는 기능 문서와 현재 Applemint 구조를 바탕으로 한 분석 판단이다.

| --- | --- | --- | --- |

| 독립성 | 낮음 | 낮음 | Raindrop 의존은 낮출 수 있으나 DB·호스팅·AI 공급자 의존은 남음 |

### A. Raindrop 유지의 장점

- **지금의 문제를 빨리 해결할 수 있다.** Pro의 정리 기능과 Stella를 쓰면 대체 서비스가 완성될 때까지 기다리지 않아도 된다.
- **저장 습관을 유지한다.** 기존 앱·브라우저 확장·컬렉션·태그를 계속 사용한다. [공식 제공 플랫폼](https://raindrop.io/pro/buy)
- **개발·운영 시간을 아낀다.** 범용 URL 파싱, 검색, 모바일 동기화, 아카이브 처리와 서버 운영을 새로 맡지 않는다.
- **원문이 사라져도 남은 복사본을 활용할 수 있다.** 다만 아카이브 가능한 콘텐츠에는 제한이 있다. [웹 아카이브](https://help.raindrop.io/web-archive)

### A. Raindrop 유지의 단점

- **Free만 유지하면 현재의 내장 정리 기능 부족은 남는다.** 수작업이나 별도 분석 도구에 드는 시간도 비용이다.
- **개인별 리뷰 기준을 완전히 통제하기 어렵다.** 예를 들어 “읽음 확인 후 30일에 다시 평가”나 주제별 보관 기준이 원하는 형태로 제공되는지는 확인되지 않았다.
- **기능과 아카이브가 구독에 묶인다.** Pro 종료 시 북마크는 유지되지만 웹 아카이브는 접근할 수 없고 약 한 달 뒤 영구 삭제된다고 공식 문서는 설명한다. [구독 종료 후 동작](https://help.raindrop.io/premium-features)
- **링크 검사와 AI도 완벽하지 않다.** 검사 오탐과 요약 오류를 검토하는 사용자 책임은 남는다. [링크 오탐 안내](https://help.raindrop.io/broken-links), [Stella 한계](https://help.raindrop.io/stella)

### B. 자체 서비스의 장점

- **저장에서 정리까지 하나의 흐름으로 묶을 수 있다.** “저장 → 링크 검사 → 컬렉션 분류 → 다시 검토 → 유지/정리”를 Applemint의 실제 사용 방식에 맞춘다.
- **미사용 판단을 명시적으로 설계할 수 있다.** 관측된 열기, 읽음 확인, 보류 사유, 마지막 리뷰 결과를 서로 다른 기록으로 보존할 수 있다.
- **AI 처리 정책을 통제한다.** 한국어 요약 형식, 원문 근거, 모델, 비용 상한, 민감한 자료 제외 여부를 선택할 수 있다.
- **데이터 모델과 내보내기를 직접 소유한다.** 리뷰 기록까지 이전 가능한 형태로 보관하고 보존 정책을 정할 수 있다.
- **현재 Applemint 기반을 활용할 수 있다.** 인증·DB·tRPC·상태 전이·예약 작업의 기존 구조가 있어 처음부터 모두 만들 필요는 없다. [통신 계층 원칙](COMMUNICATION_ARCHITECTURE.md)

### B. 자체 서비스의 단점

- **구독료가 개발비로 바뀐다.** 초기 개발, 테스트, 장애 대응, 백업 복구, 의존성 업데이트 비용은 없어지지 않는다.
- **링크 검사보다 콘텐츠 추출이 어렵다.** 로그인·유료벽·차단·자바스크립트 페이지·PDF·영상마다 접근과 추출 조건이 다르다. 텍스트가 없으면 요약을 정상 생성한 것처럼 표시해서는 안 된다.
- **완전 대체에는 저장 UX도 필요하다.** 책상 앞에서 URL을 붙여넣는 화면만으로 모바일 공유·브라우저 확장에 익숙한 실제 흐름을 대체했다고 할 수 없다.
- **스스로 데이터와 서비스 안전성을 책임진다.** 잘못된 대량 삭제, 사용자 간 정보 노출, 무제한 외부 요청, 실패한 백업을 방지해야 한다.
- **기존 이력은 새로 생기지 않는다.** 개발 이전 사용 여부는 관측할 수 없으며, 외부에서 직접 연 링크도 자동으로 알 수 없다.

## 4. 현재 Applemint에서 재사용할 수 있는 것과 없는 것

로컬 소스에서 확인한 Raindrop 연결은 [메뉴의 외부 링크](../app/nav-menu.tsx)다. 저장 버튼의 [Quick Save](../app/main/threads/quick-save-button.tsx)는 tRPC를 통해 Applemint 항목을 `inbox → saved`로 이동한다. 추적 소스에서는 Raindrop API·가져오기·동기화 구현을 찾지 못했다. 사용자가 브라우저 확장이나 외부 공유를 통해 Raindrop을 활용하는 실제 작업 방식은 이 소스 분석과 양립할 수 있다.

| 활용 가능 기반 | 추가로 필요한 역량 |
| --- | --- |
| 기존 인증·Postgres·tRPC·서비스·저장소 계층 | 사용자가 의도적으로 저장한 북마크의 계약과 소유권 |
| `inbox / saved / trash` 상태와 태그 UI | 북마크 가져오기·중복 판단·삭제 복구 |
| 예약 크롤링·재시도·YouTube 메타데이터 작업 패턴 | 임의 URL의 안전한 검사·본문 추출·AI 작업 관리 |
| 기존 PWA·공유 UI | 실제 기기의 북마크 저장·리뷰 진입점 |

현재 YouTube 메타데이터는 제목·썸네일·길이 등의 표시 정보이며 본문이나 자막의 AI 요약을 뜻하지 않는다. [항목·미디어 계약](../contracts/thread.schema.ts)

자체 개발 시에도 [기존 통신 경계](COMMUNICATION_ARCHITECTURE.md)에 따라 `UI → tRPC → service → repository/adapter → RPC/DB`를 유지하는 것이 자연스럽다. 수집된 커뮤니티 글 전체를 사용자의 북마크로 간주하면 의미가 달라진다. 사용자가 직접 저장·가져오기한 집합이 북마크 라이브러리의 기준이어야 한다.

## 5. 대안 A: Raindrop이 원본인 정리·분류 확장

**Raindrop에 URL·제목·태그·컬렉션의 원본을 두고 Applemint에서 검사 결과·리뷰·관측된 방문 기록과 AI 분류안을 관리하는 개인용 확장 방식**이다. 승인된 컬렉션 생성·이동·휴지통 이동은 Raindrop 원본에 반영하고 다시 조회해 확인한다. Applemint가 컬렉션 원본을 별도로 소유하면서 양쪽을 대칭 동기화하는 범위는 현재 필요하지 않다.

공식 API는 컬렉션 생성·수정과 북마크의 소속 컬렉션 수정을 문서화한다. 이로써 분류안을 실제 라이브러리에 적용하는 경로를 설계할 수 있지만, 사용자의 Free 계정에서 동작하는지와 허용 범위는 아직 검증하지 않았다. [컬렉션 API](https://developer.raindrop.io/v1/collections/methods), [북마크 수정 API](https://developer.raindrop.io/v1/raindrops/single)

장점은 기존 저장 습관을 유지하면서 필요한 정리만 개발하고 Pro 구독을 필수로 삼지 않는다는 점이다. AI 분류는 제목·URL·기존 태그·설명으로 먼저 수행하고, 판단이 어려운 항목만 본문을 추가로 읽는 방식을 제안한다. 짧은 메타데이터의 분류 품질은 실제 북마크로 검증해야 한다. AI는 컬렉션 구조와 항목별 이동 사유를 제시하며, 사용 여부를 추측해서 확정하거나 삭제를 단독 결정하지 않는다.

단점은 **구독을 없애도 개발·동기화·AI 실행 비용은 남는다는 것**이다. Raindrop 항목이 삭제·수정될 때 리뷰 기록과의 관계를 처리해야 하고, 토큰 만료·호출 제한·API 장애도 운영해야 한다. Applemint를 거치지 않은 방문 기록은 계속 보이지 않는다. AI API를 사용한다면 사용량 비용을 별도로 확인해야 하며, 기존 AI 서비스 구독이 API 비용도 포함한다고 가정하지 않는다.

초기 범위에서 전체 원문 아카이브, 전체 북마크 요약, 의미 검색, 공개 다중 사용자 서비스를 제외하면 재구축 범위를 줄일 수 있다. 요약과 본문 추출은 컬렉션 분류·링크 정리를 이용하기 위한 필수 경로로 만들지 않는다. 현금 추가 지출을 최소화하려면 기존 인프라의 여유와 보유 장비에서의 실행 가능성을 먼저 확인해야 하며, 무료 운영이 보장됐다고 주장하지 않는다.

### API와 이용 조건에서 확인한 경계

- 일반 REST 조회·저장·수정·삭제 문서에는 Pro 조건이 명시되어 있지 않으며, 공식 Free 계획도 가져오기·내보내기와 연동을 제공한다. **모든 API 기능이 Free라는 의미는 아니다.** 실제 Free 계정의 호출은 검증하지 않았다. [CRUD 문서](https://developer.raindrop.io/v1/raindrops/single), [계획 안내](https://raindrop.io/pro/buy)
- OAuth REST는 사용자당 분당 최대 120회, 목록 조회는 페이지당 최대 50개다. 북마크 수가 `N`개라면 목록 전체 읽기에 최소 `ceil(N/50)`회가 필요하고 상세·본문·수정 호출은 별도다. [API 호출 한도](https://developer.raindrop.io/), [목록 API](https://developer.raindrop.io/v1/raindrops/multiple)
- REST OAuth 문서는 토큰 갱신과 약 2주 만료를 설명하지만 세부 읽기 전용 `scope` 선택은 문서화하지 않는다. 앱이 읽기만 수행해도 공급자가 제한한 읽기 전용 토큰이라고 단정할 수 없다. [OAuth 문서](https://developer.raindrop.io/v1/authentication/token)
- 아카이브 API `GET /raindrop/{id}/cache`는 Pro 복사본으로 이동하는 307 응답이다. 모든 원문을 별도 요금 없이 제공하는 일반 본문 API로 해석하면 안 된다. [아카이브 API](https://developer.raindrop.io/v1/raindrops/single)
- 공식 Help는 Free MCP의 텍스트·의미 검색 제한을 설명하지만 Developer MCP 문서는 Pro 전용이라고 설명하여 일치하지 않는다. Free를 기반으로 계획할 경우 실제 허용 도구를 확인해야 한다. [Help MCP](https://help.raindrop.io/integrations/mcp), [Developer MCP](https://developer.raindrop.io/mcp/mcp)

**API 사용 조건은 중요한 사업·구조 제약이다.** 공식 지침은 확장을 권장하면서도 API 또는 Raindrop 데이터를 이용해 Raindrop을 복제·대체·경쟁하는 서비스를 만드는 것을 제한하고, 허용 여부가 불명확하면 개발자가 문의해야 한다고 명시한다. 따라서 API로 연결되는 공개 대체 서비스를 당연히 허용되는 경로로 계획할 수 없다. 개인용 확장과 서비스 공개의 적용 범위는 공급자에게 확인해야 한다. 이번 조사에서 문의나 허용 판정은 수행하지 않았다. [공식 API 이용 조건](https://developer.raindrop.io/terms)

## 6. 데이터 이전은 링크와 아카이브를 나누어 확인한다

Raindrop은 HTML·CSV·TXT 내보내기와 다른 서비스로 이동하는 용도를 공식 안내한다. HTML은 범용 북마크 이전, CSV는 필드 비교와 분석에 적합하다. 업로드한 원본 파일은 일반 백업과 별개 ZIP 경로이며, 웹 아카이브에는 개별 Download가 있다. 따라서 “내보내기 가능”과 “아카이브까지 대량·무손실 이전 가능”은 구분해야 한다. [내보내기](https://help.raindrop.io/export), [웹 아카이브 다운로드](https://help.raindrop.io/web-archive)

Raindrop으로 다시 가져올 때는 중복 URL을 건너뛰고 기존 항목을 덮어쓰지 않는다고 문서화되어 있다. 내보낸 파일을 다시 넣으면 모든 상태가 완전히 복구된다고 가정해서는 안 된다. [가져오기 동작](https://help.raindrop.io/import)

링크 검사와 원문 보존도 별개다. 아카이브는 접근 가능한 내용을 저장하는 기능이므로, 이미 사라졌고 복사본도 없는 본문을 Pro 가입이나 새 서비스 개발로 소급 복구할 수 있다고 보장할 수 없다. 이는 [아카이브의 접근 제한](https://help.raindrop.io/web-archive)을 바탕으로 한 분석 판단이다.

이전을 결정한다면 항목 수뿐 아니라 폴더·태그·메모·하이라이트·날짜·첨부 파일·아카이브를 별도로 대조해야 한다. 이는 제안하는 검증 기준이며 이번 조사에서 실제 파일 내보내기나 복원은 하지 않았다. 일반 내보내기의 이동 지원과 API의 대체 서비스 제한은 서로 다른 문서에 설명되어 있으므로, API를 이용하는 서비스의 권한을 내보내기 지원만으로 확정하지 않는다.

## 7. 비용은 구독료와 총비용을 비교한다

동일 기간 `Y`년에 대한 비교식은 다음과 같다. `P`는 실제 세금·환율을 반영한 연간 구독료, `H`는 시간, `R`은 시간 가치다. 개발·운영 시간은 아직 측정하지 않았으므로 확정 견적을 제시하지 않는다.

```text
Raindrop 유지 = Y × P + 정리·리뷰에 쓰는 시간 × R
자체 개발 = 초기 개발 시간 × R
          + Y × (추가 인프라·저장·검색·AI 비용 + 연간 운영 시간 × R)
          + 데이터 이전·검증 비용
혼합형 = Y × P + 확장 개발·동기화·운영·AI의 추가 비용
```

기존 Applemint의 DB·호스팅에 여유가 있으면 초기 추가 청구액이 작을 수 있다. 여유 자원은 무제한이 아니며 사용량 증가·백업·저장 기간에 따른 비용도 확인해야 한다. 개인용 도구와 다중 사용자 서비스의 비용·격리·지원 책임도 다르다.

AI는 다음처럼 계산해야 한다. 특정 모델을 선택하지 않았으므로 현재 모델 가격을 임의로 대입하지 않았다.

```text
월 AI 비용 = Σ(입력 토큰/1,000,000 × 입력 단가
             + 출력 토큰/1,000,000 × 출력 단가)
           + 필요시 임베딩·재검색·추출 비용
```

월 신규 북마크 요약만으로 끝나지 않는다. 초기 `N`개 일괄 요약, 추출 실패 재시도, 원문 변경, 모델 교체에 따른 재생성 비용을 포함한다. 요청할 때만 요약하고 원문 버전별 결과를 재사용하는 방식은 비용을 줄이는 선택지다. 로컬 모델도 전기·메모리·장비·운영 시간 비용이 남는다.

경제성은 `자체 개발이 추가로 절약하는 시간의 가치 + 독립성·맞춤 흐름의 가치`가 `개발·운영·이전의 추가 비용`을 넘는지로 판단한다. 다만 **시간 가치와 실제 현금 지출은 별개**다. 사용자가 구독료 지출을 부담으로 명시했으므로, 현재 선택에서는 추가 구독 없이 필요한 기능을 확보하는 경로를 우선한다. 개발 시간이 더 들 수 있다는 사실은 남지만 이를 이유로 사용자가 제외한 구독을 다시 필수로 권하지 않는다.

## 8. 자체 개발에서 피할 수 없는 작업

| 작업 | 실제 실패 조건과 영향 | 필요한 대응 |
| --- | --- | --- |
| 링크 상태 검사 | 인증·차단·일시 장애를 죽은 링크로 오판하면 필요한 자료를 삭제함. 발생률은 실제 라이브러리에서 측정 필요 | 상태를 원인별로 구분, 재검사, 사용자 확인, 휴지통 복구 |
| 중복 정리 | 의미 있는 URL 쿼리 또는 서로 다른 메모를 합치면 정보 손실 | 안전한 URL 비교와 정보 병합 판단, 확인 전 자동 영구 삭제 금지 |
| 외부 URL 접근 | 임의 URL·리다이렉트가 내부망 접근으로 이어질 수 있음. 확률은 입력·배포 환경에 따라 다르지만 영향은 큼 | 실제 연결 대상의 주소 검증, 내부망 차단, 시간·크기·동시성 제한 |
| AI 요약·정리 | 본문에 포함된 지시가 도구 동작에 영향을 주거나 근거 없는 요약을 생성 | 원문을 신뢰하지 않는 입력으로 처리, 출처 표시, 데이터 변경은 별도 검증·확인 |
| 장기 보관·복구 | 작업 성공 표시와 실제 저장·복원이 다르면 자료가 손실됨 | 저장·읽기·백업 복원을 실제 인터페이스로 검증 |

Raindrop도 링크 표시는 확정 판정이 아니라고 안내하고 검사 강도를 나눈다. 자체 구현의 오탐 처리는 장기 운영의 핵심이다. 외부 요청과 AI의 경계는 각각 OWASP의 SSRF·간접 프롬프트 인젝션 지침을 참고할 수 있다. [링크 검사 동작](https://help.raindrop.io/broken-links), [OWASP SSRF](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html), [OWASP LLM 입력·권한 경계](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)

## 9. 공통 기능 우선순위

| 우선순위 | 기능 | AI 역할 |
| --- | --- | --- |
| 1 | 죽은 링크 후보 검사·재검사·확인 후 휴지통 이동 | 네트워크 검사로 처리. AI 불필요 |
| 2 | 미사용 후보를 검토하고 유지·정리 결정 | 관련성·정리 사유를 보조. 실제 사용 여부는 기록과 사용자 판단 |
| 3 | 컬렉션 구조 제안·생성·북마크 이동 | 주제 분류와 컬렉션 이름·구조·이동안을 제안 |
| 4 | 중복 후보와 분산된 태그 정리 | 기본 중복은 규칙, 의미상 유사한 항목은 보조 분류 |
| 낮음 | 본문·영상 요약 | 사용자가 요청한 경우에만 검토 |

공통 실제 흐름은 `기존 북마크 불러오기 → 링크 상태 검사 → 미사용 후보·AI 컬렉션 변경안 검토 → 사용자 승인 → 최종 원본에서 실제 컬렉션 생성·이동·휴지통 처리 → 재조회`다. 대안 A에서는 Raindrop, 아래 대안 B에서는 Applemint DB가 최종 원본이다. 단순 분석 파일은 초기 검토에 도움이 되지만 이 흐름 전체의 완료를 대신하지 않는다. Raindrop 가져오기는 기존 URL을 덮어쓰지 않으므로 CSV를 수정해 다시 가져오는 작업을 Raindrop의 기존 컬렉션 이동·삭제 자동 적용 경로로 삼지 않는다. [가져오기 동작](https://help.raindrop.io/import)

기존 이력이 없는 항목은 `미사용`으로 확정하지 않고 별도 리뷰 후보로 표시한다. 오래됨, 현재 관심 주제와의 거리, 중복 여부는 검토 우선순위의 근거이며 자동 삭제의 근거로 쓰지 않는다. 도입 이후 관측한 방문과 명시적인 유지·정리 결정을 보존해 후보 품질을 높인다.

평가에는 삭제된 링크, 로그인 요구 링크, 일시 장애, 중요한 오래된 북마크, 태그·메모가 다른 중복을 포함한다. 링크 오탐, AI 컬렉션의 유용성, 승인 후 실제 생성·이동·휴지통 반영, 취소·복구 결과, 정리에 쓰는 시간과 추가 현금 지출을 확인한다. 이 평가는 다음 의사결정을 위한 제안이며 이번 조사에서 수행한 결과가 아니다.

## 10. 확정안: Applemint DB가 원본인 일회 가져오기·직접 저장·정리

사용자가 Q1~Q10으로 확정한 제품 정책이다. 기존 Raindrop 컬렉션과 북마크를 가져와 Applemint의 라이브러리를 만들며 이후 신규 항목은 Applemint에서 직접 저장한다. 기존 수집 글 목록과 북마크 라이브러리의 목적은 구분하고, 현재 인증·서비스·저장소·DB 경계는 재사용할 수 있다. 구체적인 테이블·AI 실행 환경·저장 UI 구현은 아직 정하지 않았다. 제품 정책 확정은 구현 시작이나 실제 데이터 변경의 완료를 뜻하지 않는다.

| 책임 | 확정한 소유 서비스·범위 |
| --- | --- |
| 최초 기존 데이터와 원래 컬렉션 정보의 유입 | Raindrop Free, 휴지통 제외, 일회 가져오기 |
| 현재 컬렉션·분류·정리 상태 | Applemint DB |
| 링크 검사 결과·방문 관측·리뷰 이력 | Applemint DB |
| 새 저장의 진입점 | Applemint 직접 저장. Raindrop 앱·확장 경유는 필수 조건이 아님 |
| Raindrop으로 정리 결과 되쓰기·후속 동기화 | 수행하지 않음 |

**장점:** 최초 가져오기 이후 저장·정리와 AI 분류가 Raindrop API에 의존하지 않는다. 직접 만든 컬렉션, 휴지통과 리뷰 이력을 한 DB에서 일관되게 관리할 수 있다. 양방향 충돌 처리나 지속적인 외부 동기화 운영도 필요하지 않다.

**부담과 한계:** Raindrop에는 정리 전 자료가 남고 이후 두 라이브러리는 달라진다. Applemint에서 직접 저장하는 실제 진입점이 필요하며 보관·백업·복구·AI 실행 비용도 직접 책임진다. 저장·분류·정리를 Applemint 안에서 자연스럽게 수행할 수 있어야 하며, 일부 이관 오류가 신규 저장 기능까지 막는 구조로 만들지 않는다.

최초 가져오기는 최상위·하위·빈 컬렉션을 조회하고, 북마크를 페이지별로 읽어 컬렉션 관계를 보존해야 한다. 미분류도 포함하며 사용자 선택에 따라 Raindrop 휴지통은 제외한다. 일반 전체 조회는 휴지통을 제외하고 페이지당 최대 50개다. URL·제목·태그·메모·날짜 등 문서화된 원본 정보를 보존하되 원본 파일·아카이브 전체 복사까지 보장하지 않는다. [컬렉션 조회](https://developer.raindrop.io/v1/collections/methods), [북마크 목록 조회](https://developer.raindrop.io/v1/raindrops/multiple), [필드 계약](https://developer.raindrop.io/v1/raindrops)

일회 가져오기에도 실패 재시도·복구가 필요하다. 같은 원본 ID를 식별하여 중복 생성을 피하고, Applemint에서 이미 확정한 분류·휴지통·리뷰 상태를 보존해야 한다. 일부 페이지 실패를 전체 가져오기 완료로 표시하거나, 가져오기 중 변한 원본 때문에 누락·중복이 발생했는데 단순 수량만으로 완료를 확정하면 안 된다. 실제 수·ID·컬렉션 관계와 실패 상태를 대조하고 불일치는 처리 결과에 남긴다. Q6 A는 기존 항목의 외부 변경을 재반영하지 않는 원칙으로 기록하되 Q5 C에 따라 후속 신규 동기화 기능을 추가하지 않는다.

기술적으로 가져오기 경로가 문서화됐다는 사실과 실제 Free 계정에서 전량 조회가 성공했다는 결과는 별개다. 후자는 아직 검증하지 않았다. API의 데이터 이용·대체 서비스 제한도 Applemint DB로 복사한다는 이유만으로 면제되지 않으므로 적용 범위를 확인해야 한다. [API 이용 조건](https://developer.raindrop.io/terms)

**정리 정책:** 죽은 링크는 반복 검사 후 후보로 표시하고 승인한 항목만 Applemint 휴지통으로 옮긴다. 미사용 후보는 오래됨·현재 관심 주제·중복 여부로 검토 우선순위를 정하고 이유를 제시한다. 과거 방문 기록이 없다는 이유만으로 실제 미사용을 확정하지 않는다. 별도 보호 대상은 `없음`으로 답했으며, 이는 자동 영구 삭제의 허용이 아니다. 정리 승인과 휴지통 복구를 유지한다.

**AI 컬렉션 정책:** 최초 컬렉션 구조와 원래 소속 기록을 보존하고 새 컬렉션·이동안을 제안한다. 사용자가 승인한 변경은 Applemint DB에 실제 적용하고 재조회한다. 요약은 필수 경로로 만들지 않는다.

정책 응답과 선택 조합의 적용 기준은 [완료된 10문항 질문지](../to-questionnaire-bookmark-db-sync-cleanup.md)에 기록했다. 구현·실제 Free 계정 가져오기·사용자 흐름 검증은 아직 수행하지 않았다.

## 조사 한계

공식 문서와 가격 미리보기, 현재 로컬 소스만 확인했다. 사용자의 Raindrop 요금제·항목 수·실제 죽은 링크 비율·요약 품질·한국 결제 금액·내보내기 복원·운영 배포는 확인하지 않았다. 코드·데이터·구독·외부 서비스를 변경하지 않았다.

남는 핵심 위험은 **이력 없는 북마크를 미사용으로 오판하는 것, 잘못된 정리로 자료를 잃는 것, 개발·운영 비용을 구독료보다 작게 보는 것, API 대체 서비스의 허용 범위를 확인하지 않고 의존하는 것**이다. 실제 데이터와 사용 흐름 검증을 거쳐 판단해야 한다.
